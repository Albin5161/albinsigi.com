Case study 03 · Mobile app · Built and live

Saw it in a video? Go there for real. A travel app that turns saved reels, posts and YouTube videos into a planned trip.

In 30 seconds

  • The problem: People save travel videos and never go. The places stay inside the video, with no map and no plan.
  • What I did: Designed and built Xplore. Paste an Instagram reel, an Instagram post or a YouTube video, and it finds every place in it, puts them on a map and plans the days.
  • Why it is different: This is not a mockup with fake data. It runs on real APIs: Gemini reads the video, Google Places finds each place, and plain rules on the phone plan the days.
  • What changed since the first version: one light look instead of two, a planner that times every stop, sign-in with a backup, and an Android test build in testers' hands.
  • See it live: the web build is at xplore.expo.app.

The problem

A travel reel names four places in 40 seconds. A YouTube vlog names ten in half an hour. An Instagram post hides them in the caption. You save it. Then you have to go back, pause, type each name into a map, and work out the order yourself. Most people stop there, so the saved folder grows and the trip never happens.

Xplore does that work for you. One link goes in. A plan you can follow comes out.

How it works

Four steps, from a link to a plan.

An honest wait

A YouTube video takes about 10 seconds. An Instagram reel can take much longer, because it has to be opened through another service first. So the wait is part of the design. The screen says what it is reading, in the link's own words: a reel, a post, a video or a Short. It shows a timer and how long it usually takes. Amma and the child keep you company, and you don't have to stay on the screen.

Real APIs, not mock data

Most design projects stop at a prototype with made-up content. I wanted to know if the idea survives real data. So every part of Xplore that looks smart is doing real work on a real server.

Google Gemini

Reads the caption, description and a post's slides, and returns a clean list of places. It also says what each place is like: how long people stay and its best time of day.

YouTube Data API

Gets the title, description and length of a YouTube video.

Apify

Opens Instagram reels and posts, which have no open API of their own. For a short reel, it can also turn the audio into text.

Google Places API

Turns each place name into a real place with an address, a location and a photo. Also runs the search when you add a place by hand.

Google Maps

Draws the map, the routes and the photo pins.

Wikipedia, Wikivoyage and Wikimedia

Free photos, city notes and travel tips, tried first before anything paid.

Supabase

The database, sign-in with an email code, the backup, and live updates when friends vote.

PostHog

Analytics, to see how people use the app. Events never carry links, places or names.

What happens when you paste a link

  • 1. The phone checks the link. If it was read on this phone in the last 30 days, the answer is instant.
  • 2. The server gets the text. YouTube's API for a video, Apify for a reel or a post. The words written on a post's slides count too.
  • 3. Gemini lists the places. It follows strict rules. It only lists places the text names, and it must leave a fact empty instead of guessing.
  • 4. Google Places finds each one. Five at a time, with coordinates and a photo.
  • 5. You confirm. Only the places you keep are saved.

Every result is saved for 30 days and shared. So if two people paste the same video, the second one costs nothing and loads at once.

Key decisions

1. AI describes the places. Rules plan the trip.

Finding place names in a messy caption is a language problem, and AI is good at that. So Gemini also says what each place is like: a sunset point, a lunch spot, a 20 minute viewpoint. It is never asked which day a place goes on, or in what order.

Planning a day is mostly maths: minutes, kilometres and what fits. So the planner is plain rules that run on the phone. It tries many ways to split your places into days, walks each day on a clock, and keeps the one that scores best. Lunch spots land at lunch, sunset points at sunset. It is instant, free, works offline and gives the same answer every time.

The trade-off: travel times are estimates from distance and terrain, not live traffic. And opening hours are not used, because Google's terms don't allow storing them.

2. Suggest, never impose

Some places are too far for a day trip. Murudeshwar is about three hours from Gokarna. So the planner also tries the trip with a night away. If that is clearly better, the plan asks you: keep Gokarna, or stay there. It never moves your bed without asking. A place that doesn't fit is not dropped quietly either. It says why, like "It fits at a packed pace."

3. The AI can be wrong, so you get the last word

The check screen says it plainly: "Xplore's AI picked these out, and it can make mistakes." Every place is shown with its photo and its area, so you can judge it in a second. A few places come as cards, one at a time: right or wrong. From six places up, cards become a chore, so it is a list you untick. Each answer is saved, so I can see where the AI goes wrong.

4. Sign-in that you can skip

The first version had no sign-up at all. That kept the start fast, but there was no backup: clear your browser and your places were gone. So I added sign-in with an email and a 6-digit code, with no password. Your places and plans are backed up, and they come back on a new phone. It is still one screen, and "Skip for now" keeps everything on the phone. Profile offers the backup again later.

5. One look, not two

Xplore used to have two looks: a sky that changed with the time of day, and a light one. Keeping both made every change three times the work. On 15 October I switched the sky off and kept the light look only. Its code is still there, but nothing new is designed for it. The app also moved to one type scale of six sizes, and one icon set.

Your places are split into Near Home and Away from home. Each city gets a real photo, picked by hand. It is never a still from the video, because a video frame was too often a person's face. A town without a photo gets the craft pattern of its state.

6. Built to stay free

Real APIs cost money, so cost became a design problem. Results are shared between users. Free Wikimedia photos are tried before Google's. Daily limits sit under each provider's free allowance. And if the counter itself breaks, the app says no instead of spending.

Plan with friends

A trip is rarely one person's choice. You can share a plan, and each person keeps, swaps or drops every stop. Votes show up live for everyone. A shared plan travels as a ticket, so it feels like something worth opening.

What testers found

Xplore is tested on real phones: on the website, on iPhone through Expo Go, and on an Android test build. Two things testers found:

  • A reel that would not read. A tester pasted a reel and nothing came out, and I had no way to see why. Now every server request writes one log line, so a failed paste can be traced.
  • A sign-in with no code. I gave the Android build to two people. Both got stuck at sign-in, because their email had a link but no code. For a new email, Supabase sends a different email, and that one still had its default text. I had only tested with my own email, which already had an account. The fix was the email text, with no new build. The lesson: always test with a brand-new account.

When things go wrong

With real APIs, things fail. Each failure has its own answer, written for people.

  • A reel or post can't be read: you add the places by search instead.
  • A video names no places: the app offers the city's best-known spots.
  • One place can't be found: that one is dropped, not the whole video.
  • Gemini fails or is too slow: it tries twice, then switches to a second model.
  • No internet: the app says so, and planning still works, because it runs on the phone.

Honest limits

  • Xplore is a working prototype, used by a small group of testers. It is not a large product.
  • The web build is live. Android is a test build shared by hand. There are no App Store or Play Store builds yet.
  • Gemini's facts about a place come from its general knowledge and are not checked. So the planner treats them as preferences, never as rules.
  • The opening scene plays a saved sample from Kochi. Every link you paste, like the Gokarna video on this page, goes through the real APIs.
  • Daily limits keep it free, so it is not built for many users at once.
